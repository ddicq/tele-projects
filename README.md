# Tele License + TeleProjects

- `bot/` — Telegram-бот (aiogram 3) + HTTP API реестра → деплой на Render
- `site/` — статический сайт → деплой на Vercel

## 1. База данных
Нужен Postgres. Проще всего Supabase (бесплатно, не удаляется): Project Settings → Database → Connection string (Session pooler)
→ это `DATABASE_URL`. Таблицы бот создаёт сам при запуске.

## 2. Чат модераторов
1. Создайте супергруппу, включите «Темы» (Topics).
2. Создайте две темы: «Заявки» и «Жалобы». Добавьте бота админом (права: отправка и удаление сообщений).
3. ID чата (-100…) и ID тем: перешлите сообщение боту @getidsbot или откройте тему в web.telegram.org —
   в ссылке `.../c/<chat>/<topic>`: chat → `-100<chat>`, topic → ID темы. Тема General = `1`.
4. Модераторами считаются администраторы этого чата (+ ID из `ADMIN_IDS`).

## 3. Render (бот)
New → Blueprint → репозиторий с этим проектом (`render.yaml`), либо Web Service вручную:
Root Directory пустой, Build `pip install -r bot/requirements.txt`, Start `python bot/main.py`. Папка `site/` Render не использует.
Переменные — из `bot/.env.example`. Health check: `/health`.
На бесплатном тарифе сервис засыпает, а бот работает через polling — используйте тариф Starter
или пингуйте `/health` каждые 5 минут (UptimeRobot).

## 4. Vercel (сайт)
Root Directory `site`, Framework Preset «Other» (папка `bot/` Vercel не использует). Перед деплоем в `site/js/config.js` укажите
`API` (URL сервиса на Render) и `BOT` (ссылка на бота). Затем в Render в `SITE_URL` — адрес сайта.

## Как работают проверки
Бот автоматически проверяет: ресурс публичный и существует, тип совпадает, число участников (≥ 5 000),
заявитель — администратор (если Telegram позволяет это узнать). Возраст ресурса, число сообщений и контент
Bot API получить не позволяет — их проверяет модератор по чек-листу в карточке заявки.

## Языки (RU / EN)
- Бот: при первом `/start` предлагает выбрать язык; сменить можно кнопкой «Язык / Language» в меню или командой `/language`.
  Язык хранится в таблице `users`. Уведомления (одобрение, отклонение, итоги жалоб) приходят на языке пользователя.
  Карточки в чате модераторов — всегда на русском.
- Сайт: переключатель RU / EN в шапке, выбор запоминается в браузере. Русские тексты лежат в HTML, английские — в `site/js/en.js`.
- Тематика, «Все страны» и «Все языки» хранятся в базе как ключи (`news`, `all`, …) и переводятся на сайте и в боте.
  Если заявитель ввёл тематику или страны своими словами, они показываются как есть.

## Аукцион номеров лицензий (Telegram Stars)
- Лоты и стартовые цены — `AUCTION_LOTS` в `bot/config.py`. При запуске бот добавляет недостающие лоты (цены уже созданных не меняются).
  Длительность, шаг и максимальная ставка: `AUCTION_DAYS`, `BID_STEP`, `MAX_BID`.
- Ставка = полный счёт в ⭐ (`currency="XTR"`, провайдер не нужен). Если ставку перебили, предыдущему лидеру автоматически
  делается `refundStarPayment`. Если возврат не удался, бот пишет в тему заявок чата модераторов с ID платежа для ручного возврата.
- Аукцион стартует с первой ставки и завершается через 10 дней: фоновая задача проверяет лоты раз в минуту.
- Номера лотов зарезервированы: обычные лицензии их не получают (счётчик их пропускает).
- Присвоение номера меняет номер ресурса в `registry`; старый номер остаётся в `license_aliases`, поэтому старая ссылка подтверждения
  и страница сайта продолжают работать и ведут на новый номер.
- Для чистой установки схема создаётся ботом сама. На уже работающей базе один раз нужна миграция
  (у `complaints.registry_id` должен быть `ON UPDATE CASCADE`) — она уже применена к проекту Supabase `tele-license`.
